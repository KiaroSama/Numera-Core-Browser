# Research refresh — 2026-11-10

## Product architecture

[Official Orbita documentation](https://gologin.com/docs/orbita-browser) says GoLogin profiles run in its Chromium-based Orbita browser, Firefox profiles are unavailable, and browser/profile native data cannot simply be converted between engines. It describes familiar browser chrome, profile isolation and upstream version tracking. These public product descriptions inform the boundary; they do not disclose or license private implementation. No privacy or undetectability marketing claim is treated as a measured Numera capability.

[GoLogin's Orbita introduction](https://gologin.com/blog/meet-the-new-antidetect-browser-orbita/) explicitly identifies the Chromium foundation. The user requested this approach after asking about the three-engine baseline. The initial Numera milestone is therefore a Chromium-derived browser plus a shared Rust control plane; other families remain explicit future paths.

## Upstream observations

Exact observed official platform versions, timestamps and source URLs are in `upstream/candidates.json`. Chromium fully rolled-out stable versions differed between Linux and Windows/macOS; source locks therefore record per-platform commits instead of guessing one universal latest version. Partial rollout/control cohorts are not selected merely because their version number sorts higher. WebKit uses an upstream revision, not an invented Safari version.

Playwright, Puppeteer and Selenium releases are observations only. Puppeteer's monorepo releases its browser-download helper separately from the automation client; the watcher filters client tags explicitly. No observed client release is declared compatible with a browser that has not been built or tested.

[Playwright's current BrowserType documentation](https://playwright.dev/docs/api/class-browsertype) confirms Chromium-only, lower-fidelity CDP attachment and matching major/minor versions for its native connection. Generic BiDi/WebSocket availability does not prove native Playwright support. Engine/tool combinations remain unsupported until real client/driver tests pass.

## Reference decisions and rights

`references.json` refreshes 17 supplied public reference entries with exact default-branch revisions, activity, archive state and declared license metadata. All remain **reference-only**. No reference engine binary, private patch, wrapper or fingerprint data set is adopted. Repository-level license metadata is not a full component redistribution audit. In particular CloakBrowser's public wrapper metadata must not be mistaken for a license to its separately distributed binaries/private patches. CEF and Rust bindings are not proof of portable engine or extension/automation parity. Servo is an architectural reference, not a pivot to a new renderer.

First-party dependencies are pinned in Cargo.lock, declared licenses/notices are inventoried, and the current OSV query is retained as local evidence. A zero-finding dependency query is not an engine security audit. Browser component compatibility, codecs/CDM rights, patch-specific licensing and complete-source delivery remain release blockers.
