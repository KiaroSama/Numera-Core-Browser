# Native build configuration observations — 2026-11-14

The development Windows source experiment reached its 330-minute budget without completing compilation. Its [downloaded report and log provenance](../evidence/cold-source-43498547353-provenance.json) retain the actual result; live action counts were never a completion estimate. Final completed compiler actions were predominantly V8, but scheduler start/finish messages include queueing and cannot establish compiler CPU time or a single bottleneck.

Chromium revision `6dc9bc3bdaea5c35ed6d41fceab2f7a3a2227c4f` selects V8 revision `307108153d1e35e6e74528ee55f97b0cd59bf182`. At that exact revision, `gni/v8.gni` defaults `v8_optimized_debug=true`, removes the default optimization config and selects `optimize_speed` on these native hosts. Therefore `is_debug=true` reduces optimization work without establishing that every source uses unoptimized compilation. The V8 file SHA-256 is `84f8ad7cdeaf946e2a5731be8dc1b4ecc92ef0213f20a59a87bd9321366b0fb6`.

The supported `v8_optimized_debug=false` alternative selects `no_optimize` and enables backtraces by default. However, `BUILD.gn` can then compile a separate optimized compiler for fast snapshot generation. Its SHA-256 is `f1d15ceec71efac112135fdc76c85e496a145a0054903a54a1e97b88eacb7711`. No native comparison proves that changing this option fits the complete graph, final link and fixtures in one permitted job. Active builds retain their frozen configuration; no new build was launched on this observation alone.

The corrected macOS ARM [capacity survey](../evidence/macos-arm-storage-43542992151.json) passed read-only measurement of all ten physical SDK directories, after separating eleven aliases. It measured 49.22 GB free, three CPUs and 7 GiB physical memory. Directory `du` values on APFS cannot prove how many bytes deletion would reclaim, and no installed assets were removed. Source-build and runtime acceptance remain unresolved.
