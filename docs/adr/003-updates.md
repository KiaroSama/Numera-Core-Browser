# ADR 003 — observe candidates before trusted activation

Feed observation implemented; installation/activation/rollback is not implemented.

The 6-hour watcher reads official Chromium per-platform stable rollouts, Mozilla version metadata, WebKit revisions and official automation-client releases. It keeps one review-only candidate branch/PR and never changes approved source locks or merges/releases automatically. Puppeteer's client releases are distinguished from its separate browser-download package. New observations are not signed or trusted update metadata.

The first hosted run observed feeds and pushed the candidate branch, then GitHub rejected PR creation: `GitHub Actions is not permitted to create or approve pull requests`. The authorized user connection created draft PR #3; after the checkout/idempotency fix, a subsequent hosted watcher run passed and updated that same PR. The user then explicitly requested merging all existing side branches, including #3. This does not enable automatic merging of future candidates.

The owner subsequently enabled **Allow GitHub Actions to create and approve pull requests** in [Settings → Actions → General](https://github.com/KiaroSama/Numera-Core-Browser/settings/actions). Verified by [run 42876574326](https://github.com/KiaroSama/Numera-Core-Browser/actions/runs/42876574326), which refreshed the actual observation timestamp and created [draft PR #4](https://github.com/KiaroSama/Numera-Core-Browser/pull/4) as `app/github-actions`. After the later authorized TinyFish settings work, a separate [permission probe](https://github.com/KiaroSama/Numera-Core-Browser/actions/runs/42890624858) created [draft PR #5](https://github.com/KiaroSama/Numera-Core-Browser/pull/5) using the actual workflow token, verified bot identity, closed it without merging and removed only its own unchanged temporary ref. [The retained report](../evidence/permission-check-42890624858.json) records all cleanup outcomes. This tests new PR creation rather than a no-op or updating an existing PR. The integration itself still cannot administer repository settings. The watcher creates draft PRs and never approves reviews or merges; PR #4 remains an unreviewed observation, not a trusted engine release.

A production updater must use reviewed, signed, expiring and rollback-resistant metadata with a documented offline trust root and key rotation/revocation. `awslabs/tough` is a reference candidate, not an adopted or validated dependency. A same-source hash alone cannot authenticate a release. Signing keys must stay out of PR jobs.

Stage in versioned directories, verify complete archives and path safety before activation, and use crash-recoverable atomic transitions. Active/recoverable sessions hold leases; activation affects eligible new sessions. No active browsing is killed and pinned engines are preserved. Garbage collection must respect leases. Binary rollback requires compatible native data or a copy-first snapshot; it cannot reverse an upgraded database by renaming a binary.

Until trust roots, metadata verification, extraction limits, staging, leases, recovery and real-data rollback tests exist, all update capabilities remain unsupported. Offline/expired metadata must fail explicitly. No source or binary release is promoted by the current workflows.
