# ADR 002 — admission and local security gate

Standalone admission primitives implemented; browser spawning and durable descendant supervision are not implemented.

`core-process::StandaloneLease` takes an explicit existing data root, acquires a real OS file lock per profile and atomically persists a bounded, strictly parsed claim with a cryptographic owner nonce. An explicit pre-spawn cancellation records `stopped`. A dropped/killed holder leaves its active claim intact; a free OS lock or reusable PID never authorizes automatic relaunch. Corruption, duplicate keys, oversize claims, unexpected state/owner edits and ambiguous ownership return `recovery_required` without rewriting the evidence. These are library primitives, not a new `session.launch` capability.

Tests exercise real separate processes, same-profile contention, independent profiles, lost replies and a killed holder. Unix checks owner UID, private directory permissions and no-follow/single-link files. Windows rejects reparse points, but full ACL validation and hard-link identity checks are still open. The caller must supply a trusted data root. Directory replacement by a hostile same-user process and power-loss recovery are not proven. No production launch is admitted through this partial boundary.

Review found two ownership-file failure cases and each was reproduced before its fix. A Unix FIFO claim could block inside `open` before regular-file validation; ownership opens now use `O_NONBLOCK` and a real subprocess test verifies bounded rejection without replacing the FIFO. A missing claim beside an existing permanent lock could be mistaken for first use; acquisition now distinguishes an exclusive first creation from opening an existing lock, and missing metadata for an existing marker requires recovery. A contender rejects an incomplete existing marker before trying its lock, so it cannot take that lock ahead of the initializer and make both attempts fail; authoritative metadata is still reread after locking. Failed first persistence also leaves this marker intact. The lock inode is never removed as a cleanup or recovery shortcut. These fixes reject ambiguity; they do not implement automatic recovery repair.

Managed mode must consume the manager's existing lease/claim admission grant rather than acquire a conflicting second lock. Standalone mode needs an equivalent Core-owned grant. Before a successful launch response, a single logical authority and durable OS ownership must exist. Windows job objects and POSIX ownership need separate tests; a process group or reusable PID alone is insufficient.

A launch ID plus idempotency key must survive lost responses without creating duplicate browsers. Recovery must reconcile durable claims and process identity. Corrupted/ambiguous ownership fails closed. Detached sessions need a surviving supervisor before the original owner exits. Cancellation must clean owned descendants before releasing admission. These are release blockers, not claims about the current code.

Only inherited stdio is implemented. Do not add a loopback debugging or control server without authentication, hostile-origin/DNS-rebinding defenses and scoped authorization. Session credentials must never grant global package administration. No tokens in URLs/command lines; use protected references and channels. Required proxy failure must never fall back to direct traffic.

Terminal stderr diagnostics use one best-effort worker with a 100 ms wait; a full inherited log pipe cannot prevent error/cancellation exit. The main thread never joins that worker or reacquires stderr. The external consumer fills an actual pipe before triggering a terminal protocol error. File-input commands open once and validate the held descriptor, with Unix nonblocking open so a substituted FIFO cannot stall before type validation. A Linux-only development interposer deterministically swaps a regular file at the open boundary for `plan`, `manifest inspect` and `hash-file`; regular-file controls also run. Neither test fixture nor development Python is a CLI runtime dependency. HTTP(S) proxy planning accepts scheme-default effective ports, rejects zero ports, and still blocks unimplemented transport without direct fallback.

Keep sandboxing, site isolation, certificate validation, GPU acceleration and safe permission boundaries. No `--no-sandbox`, certificate suppression or global web-security bypass is allowed to make CI pass. Parse requests strictly, bound frames/queues/deadlines, and never echo parser errors containing supplied data.

Authored Rust denies unsafe code by default. The single explicit exception is `core-process/src/windows.rs`, a narrow native bridge to pinned windows-sys declarations. Each unsafe block documents buffer/handle lifetime and ownership; Clippy denies undocumented unsafe blocks. `PROC_THREAD_ATTRIBUTE_JOB_LIST` assigns the child to its kill-on-close job inside `CreateProcessW`, avoiding a create-then-assign crash gap. The attribute allocation is 16-byte aligned and lives with the borrowed handle array until deletion; kernel handles use RAII, are not inherited, and cannot request breakaway. PID plus creation ticks are queried through one held process handle. An explicit environment and absolute native executable avoid parent-token inheritance, shells and PATH lookup.

Native tests use a separate development fixture executable: Unicode/space paths and argv, parent exit with surviving descendants, isolation between two jobs, rejected breakaway, and killing the owner while a descendant holds an OS file lock. Actual Windows CI exposed an important ordering boundary: its job counter can reach zero before asynchronous I/O/handle cleanup releases file locks. The test therefore requires both an empty job and the controlled descendant's OS file lock becoming acquirable within a deadline. Admission must remain active until native resource clearance is proven; neither dropping a handle nor an empty-job query alone authorizes profile reuse. This is an ownership primitive, not an approved engine, production standalone-session API, manager-grant integration, detach implementation or recovery repair. Those remaining boundaries keep `session.launch` unsupported.

Win32 references: [process creation attributes](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-updateprocthreadattribute), [CreateProcessW](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-createprocessw), and [job objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects). The atomic job-list path requires Windows 10+/Server 2016+; it has no fallback that silently weakens containment.
